# Telegram-бот для учебного центра (AlfaCRM)

Роли: преподаватель, родитель, менеджер. Данные берутся из AlfaCRM v2api,
локально хранятся только связки Telegram ↔ CRM, файлы ДЗ и заявки на перенос.

## Структура

```
alfacrm-bot/
├── main.py                  точка входа: DI, роутеры, graceful shutdown
├── settings.py              ЕДИНСТВЕННОЕ место чтения .env
├── alfacrm_client.py        клиент CRM: пагинация, лимит rps, полные update
├── cache.py                 кеш уроков в окне −30/+60 дней
├── database.py              SQLite: пользователи, ДЗ, заявки, лог напоминаний
├── scheduler.py             утренняя рассылка, напоминания, сводка, баланс
├── requirements.txt
├── .env.example
└── bot/
    ├── formatting.py        даты, карточки уроков, безопасная отправка
    ├── keyboards.py
    ├── states.py            FSM-состояния
    └── handlers/
        ├── common.py        карты имён + единая точка получения уроков
        ├── start.py         вход по телефону, выход
        ├── teacher.py       расписание, отчёт, закрытие урока, ДЗ, перенос
        ├── parent.py        расписание, ДЗ, баланс, заявка на перенос
        └── manager.py       рассылка, заявки, сводка за период
```

## Запуск

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env    # заполнить BOT_TOKEN, ALFACRM_*, ADMIN_TELEGRAM_IDS
python main.py
```

Пользователь API в AlfaCRM должен иметь роль с доступом к модулю **v2api**,
иначе все CRUD-запросы вернут Access Denied.

## Обновление с прошлой версии

1. Остановить бота, сделать копию `bot.db`.
2. Заменить файлы, добавить `settings.py`.
3. Проверить `.env` — новые ключи перечислены в `.env.example`
   (все имеют значения по умолчанию, обязательных среди них нет).
4. Запустить. Миграция схемы (`transfer_requests.author_role`) выполняется
   автоматически при старте.

**Проверить перед боем:** список `LESSON_UPDATE_FIELDS` в `alfacrm_client.py`
должен совпадать с полями, которые ваш филиал требует в `lesson/update`.

## Что исправлено

**Падения и молчаливые ошибки**

* Заявка родителя на перенос попадала в обработчик преподавателя
  (общее состояние `TransferStates` + порядок роутеров) и падала на `KeyError`.
  Состояния разделены на `TeacherTransferStates` / `ParentTransferStates`.
* Дедупликация напоминаний не работала: записывался тип `close_lesson`,
  проверялся `upcoming_*`. Теперь единый тип, проверка на конкретного
  получателя; родителям дедупликация добавлена (раньше её не было вовсе).
* `Bot(timeout=60)` — такого аргумента в aiogram 3 нет, падало при заданном
  `PROXY_URL`. Таймаут перенесён в `AiohttpSession`.
* Вход и баланс искали только страницу 0 — пользователи за пределами первой
  полусотни не могли войти. Везде полная пагинация.
* Частичный `lesson/update` (`{"status": 3}`) мог затирать время и состав
  участников урока. Теперь отправляется полная модель, текущее состояние
  берётся из кеша.
* Текст из CRM и от пользователей уходил в `parse_mode="HTML"` без
  экранирования — один символ `<` ронял сообщение. Добавлен `esc()`.
* Соединения SQLite не закрывались (`with connect(...)` только коммитит).

**Логика**

* Остаток занятий считался как `paid_lesson_count + paid_count` вместо
  разности — «остаток» только рос.
* Фильтр дат в кеше смотрел только на поле `date`, уроки с датой лишь
  в `time_from` пропадали из расписания.
* Заявки родителей нигде не сохранялись и не попадали в «Заявки на перенос».
* Кнопка переноса отсутствовала в клавиатуре урока, хотя обработчик был.
* Заявку могли одобрить и отклонить два менеджера подряд — теперь
  повторное решение отсекается на уровне SQL.

**Нагрузка**

* Кеш тянул всю историю уроков каждые 2 минуты. Теперь окно −30/+60 дней
  раз в 5 минут; хендлеры родителя и планировщик ходят в кеш, а не в CRM.
* Ограничитель 4 запроса/сек к AlfaCRM (лимит API — 5), повторы на 429/5xx,
  блокировка вокруг авторизации вместо параллельных логинов.
* Паузы между сообщениями Telegram и обработка `retry_after`; расписание
  длиннее 20 уроков отправляется сгруппированным текстом.
* Лог напоминаний чистится раз в сутки.

**Структура**

* `settings.py` вместо парсинга env в четырёх модулях.
* Все даты и задания планировщика — в часовом поясе филиала (`TIMEZONE`),
  а не сервера.
* Убраны дубли `DateRangeStates`, неиспользуемые `PhoneAuthStates`
  и мёртвый код эскалаций.
